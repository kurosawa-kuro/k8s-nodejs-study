# k8s-nodejs-study

プロジェクト設計書について、イベント駆動型アーキテクチャを使用したExpress（JavaScript）とKubernetes（Minikube + WSL）の構成を示す設計書を作成するための基本的な構成を以下にまとめます。

---

### 1. **プロジェクト目的**

* **目的**：イベント駆動型アーキテクチャによるリアルタイム処理を実現し、スケーラビリティと拡張性を高める。イベントに応じたAPIレスポンスや非同期処理を組み合わせたシステム。

---

### 2. **システム構成**

#### 2.1 バックエンド

* **言語**：JavaScript（Node.js）
* **フレームワーク**：Express.js
* **イベント駆動型処理**：

  * イベントはHTTPリクエストまたはメッセージングキュー（RabbitMQ、Kafka）で受け付け、イベントごとに非同期処理を行う
  * サーバー内でのレスポンスを非同期的に処理するために、Promiseやasync/awaitを活用
* **API**：

  * APIはRESTfulに設計し、SwaggerでAPIドキュメントを自動生成

#### 2.2 フロントエンド

* 必要に応じてフロントエンドを追加する場合、次の技術を使用する予定:

  * **Next.js**（CSR）
  * **Tailwind CSS**

#### 2.3 データベース

* **データストア**：特にイベント駆動型なので、リアルタイムで更新が必要なデータに関してはメモリ内データベース（例えば、Redis）を使用。
* **永続化**：軽量データベースとして`jsondb`または`lowdb`を利用 。

#### 2.4 メッセージング

* イベント駆動型のシステムでは、メッセージングキュー（RabbitMQやKafka）を使用して非同期処理を実現する。

  * **RabbitMQ**（非同期メッセージのやり取り）
  * **Kafka**（ストリーム処理）

---

### 3. **インフラ構成**

#### 3.1 ローカル開発環境

* **Minikube**：ローカルKubernetes環境をMinikubeで構築し、コンテナ化したExpressアプリケーションをKubernetes上でデプロイ
* **WSL（Windows Subsystem for Linux）**：Windows環境でWSL2を使用して、Linux互換環境を提供し、KubernetesとDockerを実行
* **Docker**：各サービス（Expressアプリケーション、メッセージングキュー、DBなど）をコンテナ化して、開発環境を再現

#### 3.2 クラウドインフラ

* **AWS**を使用した本番環境構築の際、次のサービスを考慮する

  * **EKS**：Kubernetesクラスタの管理
  * **S3、CloudWatch**：ログの集約・監視
  * **Lambda**（イベント駆動処理）：イベント発生時に非同期で処理を実行

---

### 4. **開発環境とツール**

#### 4.1 エディタとIDE

* **VS Code**（リモート開発：SSH接続）

#### 4.2 モニタリングツール

* **Prometheus + Grafana**：Kubernetesのメトリクス収集・可視化
* **Loki**：ログ収集ツールとして、Fluentdからデータを送信し、ログを可視化

#### 4.3 CI/CDパイプライン

* **GitHub Actions**：コードのCI（継続的インテグレーション）を自動化
* **Argo CD**：GitOpsを実現し、Kubernetesクラスタへの自動デプロイ

---

### 5. **運用とスケーラビリティ**

* イベント駆動型アーキテクチャでは、システムの負荷が増える場合でも非同期的に処理を行えるため、スケーラビリティが求められます。Kubernetesのオートスケーリングを活用し、リソースの最適化を行います。

---

### 6. **セキュリティ**

* **API Gateway**：外部からのAPIリクエストを適切に制限するために、API Gatewayを設定
* **認証**：JWT（JSON Web Token）を利用して、各リクエストに対する認証を行う
